# CalSpread Backend — External Contract (for the Go rewrite)

This document freezes the **externally observable contracts** the current Node/TypeScript
backend exposes. A replacement Go backend must preserve them exactly; internal structure
is free to change.

It is **documentation of what exists today**, generated by inspecting the source at the
time of the pre-migration hardening pass. It intentionally does not restate every large
schema — it points at the TypeScript type that is the source of truth, so the two cannot
drift.

Companion documents:
- `docs/CONFIGURATION.md` — every environment variable and its effect.
- `docs/GO_MIGRATION_BOUNDARIES.md` — how today's modules map to Go packages.
- `tests/migration-fixtures/box/*.json` — language-neutral golden fixtures the Go Box
  logic must reproduce.

> **Behaviour-freezing rule.** The frontend (`Prakash2571/Cal_Spread`) is a client of this
> API. Any change to a path, method, field name, status code, or SSE event shape is a
> breaking change and must be treated as one. When in doubt, match the TypeScript type.

## 1. HTTP API

Base: all routes are under the single Express app. CORS allows `GET, POST, DELETE, OPTIONS`
with headers `Content-Type, x-admin-token`.

### Auth model

Three distinct credentials — do not conflate them:

| Credential | Sent as | Grants |
|---|---|---|
| **Full admin** | `x-admin-token` header (24h session token from `/api/admin/verify`) | everything: trades, broker switch, live controls |
| **Trade access** | `x-admin-token` header (session from `/api/access/verify`) | trade-only role |
| **Token-route passcode** | `x-token-passcode` header or `?passcode=` | read broker access tokens + rf, nothing else |

Middleware: `requireFullAdmin` (role `full`), `requireAdmin` (either role). The session
token is an **opaque bearer string** — since the hardening pass it is 32 cryptographic
random bytes, base64url. Validation is an exact table lookup (memory + Mongo
`admin_sessions`), TTL 24h.

## 2. Streaming (SSE)

Two SSE surfaces: **market-data ticks** and **box state**. Both are `text/event-stream`,
`Cache-Control: no-cache`, `X-Accel-Buffering: no`, with a `: ping` comment every 20s.

### Market-data session lifecycle

Why sessions exist: a full board is ~816 ten-digit tokens; listing them in a URL produced
a ~9 KB request line that nginx rejects with 414. So tokens travel in a POST body:

1. `POST /api/stream/session { tokens }` → `{ id, tokens, broker, generation }`.
   - Validates tokens (finite positive ints, deduped, cap `MAX_SESSION_TOKENS`).
   - Rejects tokens not owned by the active broker with **409** (`stale_tokens`).
   - Binds the session to the current `(broker, generation)`.
2. `GET /api/stream/session/:id` opens the SSE stream.
   - **404** → unknown/expired session; client mints a new one.
   - **409** → session from a previous broker/generation; client refetches the board.
   - Acquires a refcounted browser lease (`SubscriptionCoordinator`), attaches to the
     hub fan-out, emits an immediate snapshot, then live ticks.

**Reconnect semantics.** Sessions are *looked up, never consumed* — `EventSource`
reconnects on its own, and a single-use id would kill the stream on the first blip.
Sessions are reaped only when idle with no live connection past their TTL, and are
dropped wholesale on a broker switch.

**Ownership / cleanup.** The SSE `close` handler is idempotent (fires on both `req` and
`res`); it releases the lease and detaches from the hub exactly once. Refcounts are
released *before* detaching, so a token another consumer still wants survives the
disconnect. The upstream broker socket is never torn down from a browser disconnect.

**Event format.** `data:` frames carry `Tick[]` JSON. A `kite_error` named event signals
the upstream broker session died (fatal; client stops). Comment lines (`: ping`) are
keepalives.

## 3. Broker-neutral contracts

These interfaces are the seams the strategy is written against. They map almost directly
to Go interfaces. Source of truth: `src/box/brokerContext.ts` and `src/box/brokerAdapter.ts`.

| Interface | Purpose | Go analogue |
|---|---|---|
| `BoxMarketDataProvider` | `isAuthenticated()`, `getQuoteFull(ids)` — REST snapshot quotes | `marketdata.QuoteProvider` |
| `BoxFeedProvider` | live feed: add tick/connection listeners, `retain()`, subscribe/unsubscribe, `setStrategyTokens`, `subscribedCount`, `isConnected` | `marketdata.Feed` |
| `BoxMarginProvider` | `broker`, `basketMargin(orders)` → `BoxBasketMargin` (basket-margined, `source` provenance) | `brokers.MarginProvider` |
| `BoxChargeCalculatorLike` | `legs()`, `roundTrip()`, `totals()`, rate-card version | `charges.Calculator` |
| `BoxLiveAdapterFactory` | builds a fresh `BrokerAdapter` per broker; **throws to fail closed** | `brokers.LiveAdapterFactory` |
| `BrokerAdapter` | live order I/O: place / cancel / fetch, returns broker order state | `brokers.Adapter` |

Invariants a Go implementation must keep:
- **Basket margin is asked about all four legs at once** — the offsetting benefit is the
  point. `BoxMarginSource` records which calculation produced the number
  (`kite_basket`, `dhan_multi`, `dhan_per_leg_fallback`, `unavailable`).
- **The charge calculator is injected, never branched on** — a Dhan trade must be costed
  with Dhan fees. The expected-net entry gate spends whatever this returns.
- **The live adapter factory throws on a missing key / unsatisfied static-IP** rather than
  degrading to paper.
- **Connection listeners receive current state immediately on subscribe.**

## 4. Persistence contracts

Up to six Mongo connections (see `docs/CONFIGURATION.md`): default (`MONGODB_URI`), ledger
(`TRADE_LOG_URI`), box (`BOX_MONGODB_URI`), and the three nse_fno DBs (archive/current/
spread). Collection names are contract — a Go rewrite must read/write the same names.

| Collection | Model (src) | Purpose | Restart-critical fields |
|---|---|---|---|
| `box_trades` | `src/box/model.ts` | open + closed boxes | `status`, `position_state`, `remaining_qty_by_role`, `broker`, unique open-pair index |
| `box_trade_events` | `src/box/model.ts` | append-only audit | `event`, `at`, `trade_id`, `candidate_key` |
| `box_order_intents` | `src/box/model.ts` | **durable order intents** — the recovery backbone | `client_order_id` (unique), `broker_order_id` (unique sparse), `state`, `broker`, `broker_correlation_id`, `filled_quantity` |
| `box_execution_attempts` | `src/box/model.ts` | one row per execution attempt | `resolved`, `resolved_at`, `broker` |
| `box_daily_pnl` | `src/box/model.ts` | per-day realised P&L | unique `{day, trade_id}` |
| `trades` | `src/db.ts` | calendar trades | `symbol`, `status` |
| `trade_log` | `src/db.ts` | charges/P&L ledger | `trade_id`, `at` |
| `kite_session`, `dhan_session` | `src/db.ts` | broker sessions (single-doc) | `access_token`, `expiry_time`, `login_date` |
| `active_broker` | `src/db.ts` | persisted broker selection | restored at boot before any pricing |
| `admin_sessions` | `src/db.ts` | admin session tokens | `_id`(token), `role`, `expiry` |
| `app_settings` | `src/db.ts` | rf rate etc. | — |
| `hourlyprices`, `stock_futures`, `spread_daily`, `spread_summary` | `src/db.ts` | capture data | unique compound keys per collection |

> **Recovery depends on `box_order_intents` reflecting reality.** An in-flight order must
> never be resolved to an invented terminal state. On restart the engine adopts open
> boxes from `box_trades` and reconciles unresolved intents through the broker that
> created them — never by guessing.

## 5. State machines

### Durable order intent — `box_order_intents.state`
Source: `src/box/model.ts`.
```
CREATED → SUBMITTING → ACKNOWLEDGED → OPEN → PARTIALLY_FILLED → COMPLETE
                                     ↘ CANCEL_REQUESTED → CANCELLED
                                     ↘ REJECTED
   (any) → UNKNOWN → RECONCILIATION_REQUIRED
```
`UNKNOWN` / `RECONCILIATION_REQUIRED` are the "we are not sure what the broker did" states;
they must force reconciliation, never a fabricated fill.

### Broker order status — adapter layer
Source: `src/box/brokerAdapter.ts`, `types.ts`.
```
CREATED, SUBMITTED, IN_FLIGHT, PENDING, OPEN, PARTIALLY_FILLED, FILLED,
COMPLETE, TIMED_OUT, CANCELLED, REJECTED, FAILED, UNWOUND, UNWIND_FAILED
```
`UNWOUND` / `UNWIND_FAILED` belong to the emergency-unwind path after a partial fill.

### Box position geometry — `box_trades.position_state`
Source: `src/box/positions.ts` (frozen in `position-state.json` fixtures).
```
BOX  ·  PARTIALLY_EXITED  ·  RECOVERY  ·  FLAT
```
`FLAT` iff every role's remaining qty is 0. `RECOVERY` is sticky until genuinely flat.

### Box trade lifecycle — `box_trades.status`
```
OPEN → CLOSED
```

> Do not invent states that are not in this list. These are the exact string literals the
> code and the persisted documents use.
